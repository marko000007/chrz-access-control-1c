# Режим без автоматического старта платформы

По просьбе пользователя запуск окон1С запрещён по умолчанию. OneCRuntime проверяет режим до создания файла запроса и subprocess. Команды подготовки, платформенныйCLI и прежние нативные/browser-верификаторы также имеют guard. Их отказ не означает, что код1С проверен заново.

Без платформы доступны вход/техническая база, локальная staff-диагностика, форма открытия известногоID и собственные незавершённые действия. Карточка и изменение предметных записей требуют действующего локального сервиса1С; бизнес-данные не подменяются Python.

Старый интерактивный режим включается только оператором: `--allow-gui-1c` уrun_local/local_erp/нативных верификаторов, `--allow-gui` уscripts/one_c.py либо явно заданнаяONE_C_ALLOW_GUI=1. В нём каждыйRPC способен открыть окно. Это не решение постоянного обмена без окон и автоматически не применяется. Agent-планировщик продолжает соблюдать запрет таких запусков независимо от наличия ручного флага.

Для Python-проверок флаги не нужны. Отдельный scripts/verify_offline_portal.py проверяет только локальные технические страницы в изолированной копии с фиктивными аккаунтами и отключённым бинарником; запускается QA-интерпретатором сPlaywright. Он не проводит нативную бизнес-приёмку.

Полный способ обмена без всплывающих окон, обновление обычнойdevelopment-базы послеpresenceAPI и новая нативная приёмка остаются открытыми. Пользовательские базы, ключи и существующие пароли не сбрасывать.

24 ноября: очередь команд использует короткие SQLite IMMEDIATE-транзакции и блокировку владельца; сетевой callback выполняется после commit. До20 форм, без автоматического вытеснения. Flock-слот одного оператора (macOS/Linux) предотвращает два одновременных запроса; пустой файл блокировки остаётся намеренно, чтобы не возникала гонка inode. Отказ текущего повтора не стирает неизвестный исход прошлой попытки.

На странице незавершённых действий можно скачать личную JSON-копию очереди с ключами/содержимым. Хеш описывает диагностическое представление, не исходные байты сети и не исполнение в1С. Импорт и автоматическая повторная отправка выгрузки не предусмотрены.

`scripts/verify_command_concurrency.py` воспроизводит четыре сценария двумя соединениями отдельной файловойSQLite; RPC не выполняется. Python-клиент и локальный шлюз отклоняют неоднозначный JSON, слишком глубокие структуры и NaN/Infinity и переполнение чисел; клиент принимает только окончательный HTTP200 и сверяет идентификатор подтверждения отзыва. Эти проверки протокола не подтверждают изменения нативной платформы.
