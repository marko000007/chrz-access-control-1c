# Проектные правила пропускного цикла

Правила разработаны для учебного приложения; фактический регламент организации не исследован.

Согласованная заявка допускает один пропуск. Выдавать и отзывать могут guard/admin. Повтор выдачи не создаёт копию, отозванный пропуск не восстанавливается. Автор/время выдачи и реквизиты заявки неизменяемы; отзыв хранит автора/время/причину.

Вход требует active, согласованной заявки, действующих справочников, назначенной точки и срока starts_at≤сейчас<ends_at. Внутри/снаружи меняется атомарно с неизменяемым событием. Двойной вход и выход из положения снаружи отклоняются. Для отмеченного внутри посетителя выход допускается после отзыва/истечения срока. Это ручной учёт, физические устройства не управляются.

Все записи выполняются в транзакции серверной команды1С; состояние пропуска блокируется и роль повторно проверяется. HTTP-повтор с прежним UUID не создаёт нового события. GET/passes и GET/events ограничены последними100 доступными строками; заявитель получает только свои.

Реальные15 HTTP-проверок в отдельной qa-базе включают выдачу/повтор, вход/повтор/один факт,409двойного входа, отзыв/выход, запрет нового входа по отозванному пропуску и ровно два события. Nativeсамопроверка дополнительно проверяет отказ несогласованной заявке и чужой роли. Отчёт: reports/1c-passes-http-v1.json.
