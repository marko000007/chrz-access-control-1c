# Полный локальный запуск с1С

Установленная учебная1С 8.3.27.1606 используется как настоящий исполнитель правил и хранилище предметных данных. Однократная подготовка:

```sh
.venv/bin/python run_local.py --setup-demo --check
```

Команда собирает конфигурацию, применяет технические миграции портала, создаёт недостающие вымышленные аккаунты demo.admin, demo.requester, demo.approver, demo.guard и начальные данные1С. Существующие логины, пароли и роли Django не меняются. Начальные случайные пароли новых аккаунтов находятся только в `.local/demo-accounts.json` с правами0600; файл не включён вGit.

Затем запускайте `run_local.py` без параметров вIDE и открывайте http://127.0.0.1:8044 . Настройка адаптера `.local/local-erp.json` читается автоматически. Сервер и адаптер слушают только loopback, ключ адаптера генерируется локально. Остановка портала завершает его HTTP-адаптер. Одновременно файловая учебная1С исполняет одну команду.

На этом Mac в установленном комплекте отсутствуют ibsrv/ibcmd/webinst. Файл1cv8s — интерактивный запуск клиентов, его нельзя считать автономным HTTP-сервером. [Руководство1С, приложение1.2](https://1c-dn.com/library/tutorials/1c_enterprise_administrator_guide_file_mode_8_3_27/) описывает назначение этих компонентов. Поэтому локальная поставка использует HTTP-адаптер Python и фиксированный файловый RPC к реальному процессу1С. Это выбранный способ работы с установленным комплектом; собственный нативный HTTP-сервис1С и его многопользовательская аутентификация остаются отдельным открытым критерием.

Каждый предметный ответ вычисляет1С. У Python нет копии предметной БД и собственных решений о согласовании. Запрос HTTP требует служебного ключа, Origin/чужой Host отклоняются. В1С actor сопоставляется с действующим PortalUsers. RPC-каталог закрыт правами0700; серверная точка не принимает параметры и читает только фиксированный файл внутри текущей файловой базы. Ответ проверяется по UUID вызова. Ключ команды и её результат сохраняются атомарно в1С, поэтому потеря ответа допускает точный повтор. Даты на границе API — ISO8601 с часовым поясом, до секунды; внутри обмена UTC.

`python scripts/verify_erp.py` создаёт отдельную отмеченную qa-базу и проверяет настоящий HTTP→процесс1С: создание/повтор,409при изменённом payload,роль,изоляцию,согласование и часовой пояс. Транспортные тесты с заглушкой и реальные испытания отмечаются отдельно. Отчёт — reports/1c-http-v1.json.
