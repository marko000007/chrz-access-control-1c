# Проверка локального комплекта

Для проверки нужен установленный Chrome и отдельный Python с Playwright:

```sh
python3 -m venv .qa-venv
.qa-venv/bin/python -m pip install -r requirements-qa.txt
.venv/bin/python scripts/verify_local_install.py --browser-python .qa-venv/bin/python
```

Скрипт копирует только отслеживаемые Git файлы в отдельный временный каталог, создаёт новый venv и устанавливает требования. Проверяются зависимости, 27 тестов, пустая техническая база, сборка настоящей пустой 1С из XML/BSL и начальные вымышленные данные. Исходные личные базы, ключи и аккаунты не копируются.

Затем портал запускается из другого cwd на loopback, проверяются главная/CSS. Chrome в отдельных браузерных контекстах проходит создание заявки, согласование другим пользователем, выдачу, вход, отзыв и выход через реальную 1С. Журнал содержит ровно два события; заявитель не может согласовывать. Ширины 1440 и 390 проверены, мобильные строки оформлены карточками со всеми полями внутри экрана. Снимки в reports/local-visual-v1 визуально проверены.

Результат сохраняется в reports/local-install-v1.json с SHA исходников и версиями. Собственные серверы и браузер закрываются, временные данные удаляются. В штатный запуск Playwright не входит. Используется [официальный канал Chrome Playwright](https://playwright.dev/python/docs/browsers#google-chrome--microsoft-edge).

Проверка не является полным аудитом доступности, всех экранов или других браузеров. Учебный файловый адаптер не заменяет нативную многопользовательскую аутентификацию 1С. Дополнительные реальные транспортные сценарии — scripts/verify_erp.py и reports/1c-passes-http-v1.json.
