# Работа с пропусками

Заявитель создаёт заявку с посетителем, сотрудником, точкой, целью и сроком. Отправленная заявка ожидает решения и не даёт права входа. Согласующий принимает или отклоняет заявку; собственное согласование запрещено. Заявитель может отменить свою ожидающую заявку.

Сотрудник проходной открывает согласованную заявку и подтверждает выдачу пропуска. В списке «Пропуска» видны срок, состояние и положение посетителя. Вход доступен для действующего пропуска в пределах срока; повторный вход из положения «Внутри» отклоняется. После выхода положение меняется на «Снаружи». Отзыв требует причину и запрещает последующие входы. Посетителю, уже отмеченному внутри, можно зарегистрировать выход после отзыва или окончания срока.

Действия подтверждаются отдельной формой; открытие страницы ничего не проводит. При неизвестном результате повторяйте сохранённую команду без изменений. Она сохраняется для вашего аккаунта и после нового входа. Подтверждённый отказ освобождает форму для новой попытки. Повтор команды не создаёт второй пропуск или событие. Журнал показывает последние100 доступных событий ручной регистрации.

Учётные записи и активность определяют доступ. Администратор управляет приложением; заявитель видит только свои строки, согласующий — заявки на решение, проходная — согласованные заявки/пропуска/журнал. Локальные учебные аккаунты описаны в LOCAL_ERP.md. Проектные правила не заявляются фактическим регламентом предприятия.
