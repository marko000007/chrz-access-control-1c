# Проверка сборки в чистой 1С-базе

Установленная платформа задаётся ONE_C_BINARY; по умолчанию используется локальная учебная 8.3.27.1606. Сами дистрибутив и пользовательские базы в Git не включены.

Для новой проверки выберите ещё не существующее имя базы внутри .local/1c:

```sh
python scripts/one_c.py create --base-name acceptance
python scripts/one_c.py load --base-name acceptance
python scripts/one_c.py check --base-name acceptance
python scripts/one_c.py smoke --base-name acceptance
```

Команда create не перезаписывает существующую базу. Имена ограничены буквами/цифрами ASCII, дефисом и подчёркиванием; выход за каталог проекта запрещён. Логи и JSON — .local/1c/logs/ИМЯ. Проверка создания требует файл результата с кодом 0 и наличие 1CD, smoke требует новый JSON ok=true; устаревший отчёт перед запуском удаляется. Проверяются thin/server контексты, затем реальные серверные сценарии с rollback.

22.11.2026 весь цикл прошёл в новой базе clean-20261122, созданной с нуля; источник — только XML/BSL из репозитория. Результат, SHA-256 каждого исходного файла и отметка о непроверенной локальной HTTP-связи — reports/1c-clean-build-v1.json. Это не сквозное испытание сети Python → 1С и не промышленная установка.
