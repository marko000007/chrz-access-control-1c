# Пропускной режим ООО «ЧРЗ» на платформе 1С:Предприятие

Тема диплома: **«Разработка информационной системы для организации пропускного режима в организации на базе платформы 1С:Предприятие»**.

- Проект №4, GitHub-аккаунт: `marko000007`.
- Организация: ООО «ЧРЗ»; официальный сайт: https://chrz.ru/.
- На сайте организация описана как предприятие по утилизации шин и производству регенерата и резиновой крошки. Источник проверен 22.11.2026.
- Платформа, указанная в теме: 1С:Предприятие. Локальная учебная версия 8.3.27.1606 проверена.
- Рабочая архитектура: веб-портал на Python / Django, учёт пропусков и основные правила в конфигурации 1С, обмен через HTTP-сервис с JSON. Конфигурация проверена в локальной 1С; совместимость с индивидуальным заданием ещё требует сверки.
- Цель истории: минимум 50 содержательных коммитов после начальной загрузки; ориентир — 55–60 общих коммитов. Проект включается в общий график до 24 ноября 2026 года включительно.

Статус: работает каркас Python-портала; в реальной файловой 1С созданы шесть справочников, прикладная политика ролей и документ отправленной заявки. Проверены серверные сценарии с rollback. Согласование, выдача пропуска, проход и защищённая локальная HTTP-интеграция ещё открыты.

Предлагаемый сценарий: заявка на пропуск → согласование → выдача пропуска → регистрация входа и выхода → отчёт. Сценарий уточняется по индивидуальному заданию; фактический порядок работы проходной ООО «ЧРЗ» пока не исследован.

План: [PLAN.md](PLAN.md). Требования: [docs/REQUIREMENTS.md](docs/REQUIREMENTS.md). Прогресс: [docs/PROGRESS.md](docs/PROGRESS.md).

## Запуск портала

Python 3.12+: создайте .venv, установите requirements.txt, выполните `python main.py migrate`, затем `python main.py createsuperuser` и `python main.py runserver 127.0.0.1:8044`. Пароль вводится интерактивно и не хранится в коде. Тесты: `python main.py test tests`. Python-база содержит только техническую авторизацию; предметные записи должны приходить из 1С.

## Проверенные части

Python: вход, проверка роли по контракту 1С, список и форма заявки, обработка недоступности сервиса, сохранение команды при неопределённом ответе. 14 тестов используют локальный HTTP-имитатор; связь портала с опубликованной 1С пока не проверена.

1С 8.3.27.1606: `python scripts/one_c.py create`, затем load, check и smoke. Шесть справочников и документ Requests реально загружены; 10 серверных проверок каталогов, ролей и заявки выполнены с откатом вымышленных данных. Настройка защищённой локальной HTTP-интеграции, нативных ролей платформы и серверной идемпотентности — следующий обязательный шаг, а не готовая функция.

Исходники конфигурации — one_c/configuration, модель — one_c/schema.json. Установщик платформы и файлы 1CD/DT в репозиторий не входят. Репозиторий: https://github.com/marko000007/chrz-access-control-1c .

## Запуск из IDE

Выберите интерпретатор `.venv/bin/python`, откройте `run_local.py` и нажмите Run без параметров. Адрес: http://127.0.0.1:8044 . Подготовка и проверка: `python run_local.py --check`. Пошаговая инструкция — [docs/LOCAL_RUN.md](docs/LOCAL_RUN.md).
